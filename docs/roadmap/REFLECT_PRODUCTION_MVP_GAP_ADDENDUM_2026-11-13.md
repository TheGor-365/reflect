## Ценность MVP и архитектурная единица

Reflect должен давать проверяемый цикл **ситуация → осмысление → разрешённая рекомендация → добровольное решение → конкретный шаг → подтверждённый результат → возвращение**. «Просто поговорить» остаётся полноценным режимом без обязательного плана. Нельзя приписывать пользователю мотивы, диагнозы, выполненные действия или события только на основании текста AI. Все отношения и цифры имеют sourceRef и степень достоверности.

## Проверено

- Тематическое название сеанса видно в Sessions и Diary; системный dropdown в AI Settings заменён тематическим. Сеанс пережил navigation/reload после POST /v1/ai/reply HTTP 500.
- В старых данных Journey и Mindspace по-прежнему могут отображаться «Сеанс · дата», потому что модели читают `session.title` напрямую, не canonical `sessionDisplayTitle`.
- Journey уже имеет zoom +/−, стрелки, reset, drag/touch и фильтры (4 native `<select>`). Не дублировать это; улучшить смысл и визуальную иерархию.
- Mindspace — семантическая карта подтверждённых связей, но нет аналогичного полноценного zoom/pan и фильтра областей; native `<select>` для типа связи. ProfileModal — native `<select>` пола. Глобальный code audit обязателен: этот перечень не гарантированно полный.
- Dashboard уже показывает 7/30-day event activity и подтверждённые counts. Не переизобретать его, а переиспользовать selectors для других карт.
- Recommendations пока пусты без валидного live interaction.v1. В Beta нельзя выдавать фиктивную цель или AI-баллы.

## P0.1 · Ответ Grok и контролируемое восстановление

**Приоритет № 1.** До следующего визуального спринта реализовать owner-scoped `AiTurnAttempt` / provider receipt с состояниями `saved-user / queued / running / validated / persisted / failed-before-provider / failed-after-provider / unknown` и provenance `sessionId + sourceTurnId + requestId`. Сохранение ответа должно переживать смену страницы, закрытие вкладки и сбой сети; приватные тексты не отправлять в общие логи и не хранить в immutable budget ledger. Серверное хранилище ответа требует отдельного review, TTL и access controls.

**UI:** на сохранённом вопросе без ответа показывать «Проверить статус» (неплатное чтение квитанции), затем «Попробовать получить ответ снова» с подтверждением **возможного нового списания**, если восстановление невозможно. Новый requestID — только при явном повторе, исходный user turn не дублировать. Отдельная кнопка «Повторить только сохранение» при уже полученном ответе. Никогда silent retry: прежний immutable request ledger не допускает повтор того же requestID. Два браузера/двойной клик не должны создавать параллельные billable attempts.

**Accept:** simulated HTTP 500/timeout/incomplete JSON/Firebase failure/offline/reload → authored turn на месте, metadata редактируется безопасно, статус честен, recovery бесплатно или явно новой оплачиваемой попыткой, не появляются дубликаты сообщений/целей. P0 включает реальный Grok QA только после отдельного бюджета.

## P0.2 · Продолжить M1–M7

До полноценного MVP необходимо: реальная структурированная Grok QA, актуальные настройки, пять серверно управляемых режимов, одно уместное уточнение либо обоснованная рекомендация, readiness по подтверждённым данным, защищённая память только по явному согласию на точные предыдущие реплики (preview/revoke/expiry), user-confirmed linked goal and steps, последующий check-in. История одного аккаунта никогда не является общим контекстом по умолчанию. Поддерживающий разговор не навязывает цели.

## P1.1 · Области жизни и протокол check-in

Редактируемые пользователем фильтры **Карьера и проекты / Отношения / Привычки и обучение / Самочувствие / Финансы / Другое / Собственная область**. Все необязательны, «Без области» валидно. AI может предложить область; пользователь подтверждает. Не выводить личные категории по скрытой классификации.

Добавить явный `UserCheckIn`: areaId, sessionId, userConfirmedAt, необязательная **одна выбранная шкала 1–5** и наблюдение. «Рост», «спад», «без изменений» показывать только для **двух или более сравнимых пользовательских измерений** с датами; отсутствие данных — не ноль. Число сообщений и AI-идей не равны личностному прогрессу.

## P1.2 · Развести функциональные роли карт

**Journey («Как я двигался»):** хронология подтверждённых событий: вопрос → уточнение → предложение → решение → цель → выполненные шаги → возврат. Сохранить имеющийся zoom/pan; унифицировать 4 выпадающих фильтра, добавить область и показ/скрытие типов узлов, надёжную легенду, fit-to-view, focus source, inspector «какая связь и когда появилась». Все title через canonical selector.

**Mindspace («Что связано»):** подтверждённые человеком смысловые связи и их происхождение, а не декоративный орбитальный граф. Добавить zoom/pan/reset, фильтры `область/темы/цели/идеи AI/подтверждённые связи`, выбор 1–2 узлов и inspector с исходной записью и решениями. Никогда не рисовать причинность только по близости.

В обеих картах — доступный список событий, легенда, keyboard/touch, понятное пустое состояние; узел ведёт на точный owner-scoped source.

## P1.3 · Цифровые «Результаты», связанные с картами

- 7/30 дней: counts настоящих возвратов, пользовательских решений, записей/событий (не оценка успешности).
- Цели: `done/total` и confirmed completion timestamps; без даты показывать «за всё время», не приписывать неделе.
- Области: динамика добровольных check-in по той же шкале, количество подтверждённых действий, сколько шагов выполнено; «недостаточно данных» при коротком ряде.
- Рекомендации: ожидают решения / приняты / отклонены / отложены без автоматического достижения.
- Связи: только число пользовательски подтверждённых, не всех линий на экране.

Общий read-only selector / evidence model для Dashboard, Journey, Mindspace, Goals, Recommendations — **одинаковые числа**, единый период и кликабельный источник. Не рисовать «AI определил улучшение на 87%», «здоровье 83%», эмоциональный диагноз и другие неподтверждённые scores.

## P1.4 · Design-system и navigation audit

Три dropdown AI Settings уже обновлены. Проверить все пользовательские native `select` (как минимум 4 Journey, 1 Mindspace, 1 ProfileModal) и заменить на единый доступный компонент: alignment, z-index, overflow portal, dark/light, focus, Esc, arrows, typeahead, mobile touch, disabled, screen-reader, empty state. Не подменять чувствительные security/consent controls декоративными экспериментами. Согласовать единые имена сеансов во всех projection/models, не менять ручные названия. Проверить, почему на Recommendations в верхней панели заголовок «Reflect» вместо раздела; почему в Mindspace на скриншоте верхний заголовок обрезается.

## P0 production safety / P1 onboarding

Cross-UID/Auth/AppCheck, consent boundaries and revoke, output safety, failure and budget controls, encrypted/restricted receipt data policy, export/delete, rollback/restore, telemetry **без текста бесед**, performance and a11y/mobile/light-dark. Closed beta на новых чистых аккаунтах, не только Eric/Jack. Первый полезный разговор за 5 минут → понятный результат → добровольное действие → возвращение через дни.

**Не входит в MVP:** Apple Health, Todoist/Trello, AR/3D, рекомендации от реальных коучей/психологов, автоматический «риск» психического состояния, прогнозы с заявленной точностью. SC-291–310 остаются исследовательскими направлениями.

## Порядок исполнения / Done

1. **P0 T1 recovery and actual structured Grok response**, без скрытого повторного списания.
2. **P0 M3–M7** — согласованная memory, пять режимов, readiness, real goal and return.
3. **P1** unified titles + dropdowns.
4. **P1** добровольные области/check-in + связанные карты и числовая аналитика.
5. **P0** приватность/надёжность/экспорт/удаление + closed-beta smoke.
6. **P1** onboarding и реальная beta UX приёмка; owner GO для production release.

**Финальный acceptance loop:** сохранённый вопрос → real reply or recoverable explicit failure → рекомендация только при разрешении → решение пользователя → связанная цель/шаг → временная линия/карта/график дают одни и те же проверяемые числа → вход через 7 дней → честная динамика или «недостаточно данных». Любая failed-provider попытка не требует копировать текст и не исчезает после reload.

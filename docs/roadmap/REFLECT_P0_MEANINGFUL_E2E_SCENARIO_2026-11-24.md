## Принципы теста

1. Один **реалистичный вымышленный персонаж от первого лица** (веб-разработчик с двумя предполагаемыми заказчиками), одна проблема и последующий результат. В саму реплику не вставлять команды «это тест», «создай JSON», «сгенерируй KPI» — проверяется натуральное поведение продукта. 2. Сохранять **одну последовательную историю**, проходить: первоначальное описание → уточнение/опровержение гипотез → выбор шага/цели → ретроспективный результат → отдельный сеанс для **проверки ограничения памяти**, а не невыполнимого автопереноса истории.

Два мастера ожидают небольшой продукт записи клиентов; человек три месяца расширяет функциональность вместо раннего показа рабочей части. Обстоятельства: уже работают запись и список клиентов; уведомлений нет; мастера всё ещё используют таблицы; один спрашивал срок; реальный ресурс на неделю **6 часов**.

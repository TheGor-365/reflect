## Proposed atomic transaction contract (actual source change required; NOT implemented in B2)
**Input (server-owned after true Auth/AppCheck/entitlement and user preview approval):**
`{uid, requestId, sourceTurnId, sourceId, grantId, approvalDigest, sourceRevision, committedMessageDigest, ownerGeneration, ledgerId}`.
No transcripts, API keys, or plaintext user content in lease or budget receipt. One canonical `requestId` throughout.

**Transaction read set — ALL before any write:**
1. signed owner-scoped session/source ref with current updateTime or explicit immutable revision (recompute digest and committed last user turn against approved preview);
2. `contextGrants/{uid}/grants/{grantId}`;
3. BOTH original private/public erasure fence refs;
4. shared `pg04d4aDispatchOwners/{uid}` coordinator and canonical owner-generation phase;
5. immutable hashed `requestLedger/{sha256("request\0"+uid+"\0"+requestId)}` **ABSENCE** before budget reservation, plus `runtimeFlags/ai`, `ownerDays` and `globalDays`;
6. per-request/lease replay tombstone and optional attempt receipt if composer/claim already committed.
All checks deny malformed/partial fences, conflicting owner, old grant, stale source, duplicate id, bad balance or quota. A **single Firestore TX** must include budget reserve ledger creation, quota counters, source-bound metadata-only approval, and generation-bound lease reservation. No second TX reads after writes.

**One-shot begin dispatch TX:** re-read both fences, active grant, source revision/digest, owner generation + reserved lease, immutable ledger state, attempt identity, and kill switch; mark `dispatch-started` plus possibly-billed recovery receipt atomically where feasible. If legacy receipt cannot be composed, document every crash window and require fail-closed reconciliation. An external provider HTTP POST is NEVER part of this TX.

**Response/unknown settlement:** persist reply and private recovery receipt once, settle lease outcome; only then finalize budget without refund after unknown; leave explicit `unknownCount` quarantine with no TTL auto-release. If crash after begin before actual send, classify conservatively as potentially in-flight. If POST begins before erasure intent but arrives after intent, **defer effective deletion until resolution**; do not promise no outbound bytes after erasure-click without a separately proved gateway barrier. Old worker versions and real provider history remain OFF during rollout.
